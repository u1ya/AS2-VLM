## Итог сессии 2026-10-20

WSL2 Ubuntu-22.04 mirrored, GetState и sportmodestate работают с AS2 через
eth1 / 192.168.123.161. Разрешения UDP настроены отдельными правилами
Windows/Hyper-V; скрипт поддерживает Status/Enable/Disable.
Добавлены отдельные ручные stop/pulse/meter C++ утилиты и тесты политик.
После настройки порога вертикальной скорости до 0.5 м/с последний проезд
составил 0.969413 м по одометрии; no_progress, StopMove=0,
telemetry_stationary=1, exit=1. Полный метр не подтверждён. VLM/демо
по-прежнему не управляют физическим роботом. Камера, лидар, SLAM не подключены.

## История

- Инвентаризация: вопросы отправлены, ожидаются сведения.
- Основа проекта: создана, Python 3.10+, без runtime-зависимостей.
- Контракты и детерминированный parser: первая версия для ограниченного набора приказов.
- Dry-run и mock bridge: созданы; физические действия не выполняются.
- Проверка: 8 unit-тестов и запуск CLI с двумя действиями прошли на bundled Python; SDK и оборудование не тестировались.
- Реальный SDK bridge, сенсоры, контроллер, VLM, трекинг и деплой: ещё не реализованы.

Обновление: проверен официальный AS2 SportClient и среда SDK. Добавлены local preflight и исходник read-only C++ GetState probe с CMake. Это подготовительная часть bridge; сборка C++ и подключение ещё не проверены. Добавлен первый скрипт deploy/preflight.sh; установка и автозапуск ещё не реализованы.

Проверка обновления: все 10 Python-тестов прошли. На текущем Windows-ПК preflight вернул LOCAL_CHECKS_INCOMPLETE: нет Linux, CMake, g++ и checkout SDK. Реальное устройство не опрашивалось. Для продолжения нужна доступная целевая машина; вопрос владельцу отправлен.

Следующий зависимый шаг: выбрать среду сборки и подключить официальный SDK по данным конкретного AS2. Независимый следующий шаг: расширить набор проверочных инструкций и реализовать запись/replay событий по утверждённым контрактам.

## VLM backend

Добавлен локальный Ollama backend с моделью Qwen2.5-VL 3B, отдельными вызовами планирования и визуального grounding, строгими проверками JSON и bbox. CLI принимает --backend ollama, --image и --healthcheck. Правила остаются режимом по умолчанию для работы без runtime.

Добавлены portable bootstrap и скрипты model server для Windows/Linux, а также живой smoke-тест evaluate. Portable Ollama и Qwen2.5-VL 3B установлены, сервер работает на loopback с CUDA. Живой smoke-тест прошёл 8/8 проверок (6 известных приказов, 2 визуальных статуса/структуры). Это не оценка обобщения или точности локализации: bbox человека визуально неточна и требует уточнения. Все пути исполнения остаются PREVIEW_ONLY, SDK не вызывается.

Для сборки SDK локально WSL отсутствует. Ожидается доступ к Linux/onboard-среде AS2 и реальные потоки сенсоров. Следующий независимый этап: проверка VLM на новых формулировках и кадрах, уточнение bbox и трекинг.

Финальная проверка обновления: 26 unit/integration-тестов прошли. Добавлен run.ps1 для запуска CLI через доступный Python на Windows. Результаты живой проверки сохраняются в reports/vlm_smoke.json.

## 2026-10-19: реальный read-only доступ к AS2

В Ubuntu 22.04 WSL2 mirrored собраны официальный SDK2 и наш C++ probe.
Плата 192.168.123.161 доступна через eth1 с адреса ноутбука
192.168.123.100/24. С временными узкими по адресу разрешениями inbound UDP
в Windows и Hyper-V firewall успешно получен GetState (код 0) и телеметрия
официального as2_sport_state. Оба временных правила удалены после теста;
постоянные разрешения требуют отдельного включения. Подробности и скрипт
Enable/Disable — в sdk_notes.md и deploy/configure_dds_firewall.ps1.
Физическое управление, RGB/лидар и замкнутый навигационный контроллер
по-прежнему не интегрированы. Команды движения/позы не выполнялись.

Добавлен ReadOnlyAS2Bridge: приложение вызывает C++ probe с JSON-выводом,
ограничением времени, валидацией ответа и защитой от одновременных запросов.
CLI --robot-state и опциональный demo backend проверены на реальном AS2:
sdk_return_code=0. В браузере отдельно показан снимок GetState с временем;
реальные данные не используются как координаты симуляции. На ошибки старые
значения очищаются. HTTP endpoint ограничен loopback Host/Origin и отдельным
заголовком. Тесты backend и HTTP добавлены; поток sportmodestate остаётся
следующим этапом, а физическое управление не реализовано.
