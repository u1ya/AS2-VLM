# VLM: Qwen2.5-VL 3B через локальный Ollama

На Windows-ПК обнаружена NVIDIA GeForce RTX 5060 Laptop GPU с 8151 MiB VRAM. Первый backend использует `qwen2.5vl:3b`. NaVILA остаётся отдельным кандидатом для сравнения, адаптер NaVILA сейчас не реализован.

Источники: [модель в Ollama](https://ollama.com/library/qwen2.5vl), [vision API](https://docs.ollama.com/capabilities/vision), [chat API](https://docs.ollama.com/api/chat). Модель выбрана как компактная отправная точка, её качество на AS2 ещё предстоит измерить.

## Запуск Windows

Portable runtime устанавливается только в `.runtime`, без системного установщика. Архив официальный; bootstrap проверяет размер и SHA256 при наличии digest в GitHub release. Зафиксирована версия v0.40.2. Runtime и веса исключены из Git.

```powershell
& .\deploy\bootstrap_ollama.ps1
& .\deploy\start_model_server.ps1 -OllamaPath .\.runtime\ollama-v0.40.2\ollama.exe
```

В другом терминале:

```powershell
& .\deploy\start_model_server.ps1 -OllamaPath .\.runtime\ollama-v0.40.2\ollama.exe -PullModel
python -m as2_vlm --healthcheck
python -m as2_vlm --backend ollama "Повернись к двери и подойди к ней"
python -m as2_vlm --backend ollama --image C:\frames\room.jpg "Дойди до белой стены"
```

`python` должен указывать на Python 3.10+. Скрипт сервера работает в foreground, слушает только loopback, хранит веса в `.models/ollama`. Не запускать второй сервер на том же порту. Поддержаны только локальные HTTP endpoints; облачные сервисы не используются.

Для фонового запуска Windows есть `-Detached`: процесс создаётся со скрытым окном, stdout/stderr пишутся в `logs/ollama.*.log`, выводится PID. Это запуск процесса, а не установка службы или автозапуска. Готовность проверяется отдельно через CLI --healthcheck.

## Что проверяет этот этап

Первый вызов модели переводит приказ в план из 1–2 действий. При `--image` второй вызов предлагает bbox для каждой уникальной цели на одном кадре. Ответы проверяются независимо от модели. Неоднозначная/невидимая цель сохраняет статус ambiguous/not_found. При отсутствии изображения система выполняет только языковое планирование; визуальное обнаружение не считается проверенным.

Любой успешный CLI-результат остаётся PREVIEW_ONLY и executed=false. Bbox является предложением VLM, без трекинга, калибровки или метрической глубины. Даже найденная цель не означает, что к ней можно пройти. Для ходьбы ещё нужны SDK bridge, сенсоры и локальный контроллер.

Максимум кадра 10 MiB и 25 мегапикселей, поддержаны PNG/JPEG. Для изображений нужен `pip install '.[vision]'` (Pillow). Кадр ориентируется по EXIF и уменьшается с сохранением пропорций до 768 пикселей по большей стороне; оригинал не изменяется. Чтение ответа ограничено 1 MiB. Таймаут inference 120 секунд, temperature=0, context=8192. После измерения задержек параметры можно менять; realtime-управление от частоты VLM не зависит.

Ответ модели задаёт bbox в явно объявленной системе normalized_1000. Код проверяет целые координаты и границы, затем переводит их в доли [0,1]. Масштаб никогда не угадывается по величине чисел. Координаты относятся к ориентированному подготовленному кадру; при калибровке нужно учитывать подготовку изображения.

## Проверка качества

Снять кадры реальной камеры AS2: дверь, белая стена, один человек, несколько людей, отсутствие цели, плохое освещение. Проверять найденную область вручную; не оценивать результат по одному удачному кадру. Синтетические ответы в unit-тестах подтверждают работу клиента и валидатора, а не качество модели.

```powershell
python -m as2_vlm.evaluate
python -m as2_vlm.evaluate --demo-image .runtime/qwen-demo.jpeg --output reports/vlm_smoke.json
```

Второй запуск рассчитан именно на [демонстрационный кадр Qwen](https://qianwen-res.oss-cn-beijing.aliyuncs.com/Qwen-VL/assets/demo.jpeg) из официальной карточки модели: человек в клетчатой рубашке на пляже, двери нет. Проверяются статус обнаружения и валидность bbox, но не его точность по IoU. Это smoke-тест связи и inference, не оценка навигации AS2.

## Подтверждённое состояние

Portable Ollama 0.40.2 и Qwen2.5-VL 3B установлены в проекте. Сервер запущен на 127.0.0.1:11434, CUDA распознала RTX 5060 Laptop. Живой прогон прошёл 6 проверок известных приказов и 2 проверки статуса/структуры визуального ответа. Эти приказы представлены в few-shot промпте; результат не доказывает обобщение на произвольный язык.

Визуальный просмотр демонстрационного кадра и ответа выявил неточную bbox: она смещена вверх и не охватывает человека целиком. Автоматический smoke-тест это не оценивает. Для реального движения требуется уточнение детектором/сегментацией, проверка на кадрах AS2 и калибровка. Нельзя считать найденную bbox подтверждённым направлением или точкой подхода.
