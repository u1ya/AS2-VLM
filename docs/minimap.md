# Мини-карта AS2: минимальный вариант

Обновление 2026-11-02: живой режим проверен на роботе; по умолчанию приоритет —
человек и мусорка. Добавлена привязка кадра к конкретному облаку до распознавания
и предварительная 3D-ассоциация при наличии измеренной калибровки. Старая общая
детекция доступна через `--all-objects`. Интервал между запросами теперь 2 с.
Полные текущие ограничения, новые профили и блокировка физического движения
без LiDAR-защиты: [semantic_mapping.md](semantic_mapping.md). Текст ниже описывает
первоначальную реализацию и её прежние проверки.

Дата: 2026-11-01. Панель: http://127.0.0.1:8772/.

Панель совмещает локальную геометрию настоящего лидара AS2 с распознаванием
объектов на настоящем изображении videohub. Это рабочий просмотр окружения,
а не глобальный SLAM или семантическая карта с координатами объектов.
Без доступа к роботу проверен режим записанных данных; живой режим подготовлен
через существующий SharedSensorAdapter, но в этом сеансе на оборудовании не проверен.

## Запуск без робота

```powershell
./minimap.ps1 -Replay
```

Скрипт поднимает установленную локальную Ollama, если она выключена, проверяет
наличие qwen2.5vl:3b и открывает сервис на 8772. Страницу откройте в браузере.
Новые модели и зависимости автоматически не скачиваются.

По умолчанию используются приватные файлы этого компьютера:

- `recordings/slam-shared-cli-20261025-06` — 28 облаков, IMU и одометрия AS2;
- `logs/camera-20261025-videohub.jpg` — RGB-снимок камеры AS2, 1920×1080.

Эти файлы исключены из Git. На другом компьютере нужны собственные записи:

```powershell
./minimap.ps1 -Replay -Recording 'recordings/SESSION' -Image 'logs/CAMERA.jpg'
```

Снимок и облака записаны в разное время: они явно обозначены как непарные,
не синхронизируются искусственно и не используются для оценки расстояний.
Облака проигрываются один раз по интервалам приёма, с ограничением паузы 1 с;
после завершения последнее изображение карты остаётся архивным.
Ближайшая по времени приёма одометрия допускается только в пределах 0.3 с.
Это диагностическая привязка, а не синхронизация времени захвата.

## Запуск с настоящим роботом

На прежней Windows/WSL машине с подключённым AS2:

```powershell
./sensor-hub.ps1
```

В другом терминале:

```powershell
./minimap.ps1
```

Параметры из `configs/agent.as2-sensors.json`: Unitree AS2 EDU, WSL Ubuntu-22.04,
интерфейс eth0, DDS domain 0, videohub 1920×1080; облако frame=hesai_lidar.
После смены сети проверьте маршрут к 192.168.123.161: историческое eth0
не гарантирует правильный интерфейс после перезапуска. Хаб проверяет совпадение
профиля; панель не создаёт отдельного DDS-подписчика и не перезапускает хаб.
Одновременно могут работать прежние панели 8770/8771.

Для другого порта: `./minimap.ps1 -Replay -Port 8773`.

## Обработка и ограничения

Карта использует существующий LocalLidarGeometry: область ±16 единиц сенсора,
ячейка 0.1, срез Z от -0.1 до 1.8, окно до 30 сканов / 5 с. Масштаб отображения
переключается между ±4/8/16. При движении/смене позы накопление сбрасывается;
во время движения остаётся один скан. Это плотность отражений, тёмные ячейки
не означают свободное пространство. Единицы, оси и внешняя калибровка не подтверждены.

Для RTX 5060 Laptop 8 ГБ используется установленная Qwen2.5-VL 3B. Один поток
распознавания работает без очереди: берёт доступный свежий кадр, выполняет запрос
с таймаутом 90 с, ждёт 8 с и берёт последний доступный кадр. Ошибки видны в панели,
после них обработка повторяется. Один и тот же успешно обработанный кадр повторно
не анализируется. Геометрия обновляется независимо от медленного распознавания.

Исходный кадр для просмотра уменьшается до 768×432 с сохранением пропорций.
Для модели он пересчитывается в квадрат 768×768; нормализованные X/Y затем
показываются на исходном прямоугольном изображении. Пересчёт координат линеен,
но точность рамок самой модели не гарантирована.

Каждый ответ хранится вместе с тем изображением, на котором он получен.
Новая камера не получает рамки старого кадра. Возраст ответа показан в живом
режиме; при потере камеры последнее распознавание остаётся историческим.
Названия floor/ceiling/wall/lights исключаются из списка отдельных объектов;
отклонённые названия сохраняются в API как rejected_background_labels.
Это фильтр фоновых объектов, а не доказательство правильной классификации.

GET `/api/scene` возвращает геометрию, текущую камеру и связанное с кадром
распознавание. `motion_enabled=false`, `metric_positions=false`,
`camera_lidar_synchronized=false`, `grounding_verified=false`.
Сервис слушает только 127.0.0.1 и не имеет команд движения или POST API.

## Проверка и найденные ошибки

На сохранённых настоящих данных обработаны все 28 облаков: 1 843 непустые ячейки,
1 535 089 отражений в окне, без ошибок декодирования или сбросов позы.
Это проверка конкретной короткой неподвижной записи.

Первая модельная попытка на 768×432 распознала коробки, но поставила рамку
слишком высоко. Проверены квадратное дополнение полями и квадратное изменение
размера; второй вариант дал более близкую рамку на этом снимке. Повторный
ответ: boxes, category=obstacle, bbox=[0.158,0.330,0.480,0.513], 5.28 с.
Верхняя граница всё ещё выше коробок; плотная точная локализация не достигнута.
Также модель вопреки инструкции назвала пол препятствием с confidence=1.0.
Добавлен явный фильтр фоновых названий с сохранением отклонений в API.
Высокий confidence не является измеренной вероятностью правильного ответа.

Эта проверка не доказывает качество детекции на новых сценах. Она показывает,
что настоящая локальная модель обрабатывает изображение камеры и что ошибки
не превращаются в метрические точки карты или команды роботу.

Проверки:

```powershell
python -m unittest discover -s tests -v
```

Добавлены проверки неизменности исходного кадра, ограниченного размера входа,
сохранения связи рамок с кадром при обновлении камеры, фильтрации фона,
восстановления после ошибки модели, HTTP-доступа и отсутствия команд движения.
Приватный тест воспроизводит настоящие облака, если файлы доступны; иначе
явно пропускается. Итоговая общая регрессия прошла: 180 тестов, включая
воспроизведение приватной записи и HTTP-проверки. Скрипт PowerShell прошёл
синтаксический разбор и фактический запуск панели.

Следующий аппаратный этап — проверить живые потоки после подключения робота,
измерить задержки и свежесть, получить intrinsics камеры, LiDAR-to-camera/body
и временную калибровку. Только после этого можно проверять проекцию реальных
точек в рамки и размещать объекты на метрической карте. Для движущейся глобальной
карты дополнительно нужен проверенный SLAM; одометрическое склеивание без
известных преобразований здесь намеренно не выполняется.
